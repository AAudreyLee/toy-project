# 아이디어에서 첫 Spec까지 안내받기

사용자가 본인 Claude API 키를 넣고 agent와 대화하면서, 만들 것 찾기(필요하면 재료 제안) → 서비스 방향 → 먼저 만들 결과 하나(첫 Spec)까지 진행합니다. 진행 내내 로드맵에서 현재 단계를 보고, 끝난 단계를 골라 다시 고칠 수 있습니다. 핵심 루프의 1~3단계만 다루는 첫 결과입니다.

## Linked sources

- [PRODUCT.md](../../../PRODUCT.md) — 사용자, 핵심 루프, 재료 목록, 경험 원칙의 기준입니다. 이 spec은 그중 1~3단계와 관련된 내용만 적용합니다.
- [prototype.html](prototype.html) — 승인된 화면 구성입니다. 화면 목록, 화면별 배치, 로드맵·"지금 할 일"·대화·문서 패널의 관계, 상태별 문구는 이 파일을 따릅니다.
- [docs/decisions/llm-usage-billing.md](../../decisions/llm-usage-billing.md) — agent의 Claude API 호출은 사용자 본인 키로 합니다.
- [docs/decisions/ui-composition.md](../../decisions/ui-composition.md) — 일반 UI는 shadcn 구성과 현재 preset 토큰을 씁니다. 로드맵은 핵심 표면으로 custom UI를 허용합니다.
- [docs/decisions/deployment-ownership.md](../../decisions/deployment-ownership.md) — 이 결과에는 배포가 없지만, 잠긴 4·5단계가 나중에 따를 기준입니다.

## User-visible outcomes

- 사용자는 본인 Claude API 키 하나만 넣으면 바로 시작할 수 있습니다.
- 만들고 싶은 것이 있는 사용자는 한 줄로 적고 시작합니다. 없는 사용자는 재료 목록에서 골라 agent가 추천한 아이디어 중 하나로 시작합니다.
- agent의 질문에 답하면 서비스 방향 문서가 채워지고, 이어서 "한 번에 만들고 직접 써 볼 수 있는 결과 하나"를 담은 첫 Spec 문서가 만들어집니다.
- 사용자는 언제든 로드맵에서 지금 어느 단계인지, 다음에 무엇을 하면 되는지 볼 수 있습니다.
- 끝난 단계를 다시 고칠 수 있고, 그 때문에 뒤 단계가 어긋나면 내용은 남은 채 "다시 확인 필요"로 표시됩니다.
- 두 문서(서비스 방향, 첫 Spec)를 `.md` 파일로 내려받을 수 있습니다.

## Scope

포함:

- 시작: 본인 Claude API 키 입력과 키 확인, 키 변경
- 1단계 만들 것 찾기: 아이디어 직접 입력, 재료 목록 보기·고르기, 고른 재료로 아이디어 추천 받기·다시 받기, 추천 하나 골라 시작
- 2단계 서비스 방향: agent와 대화하며 서비스 방향 문서 채우기, 빠른 답 버튼, 방향 확정
- 3단계 첫 Spec: agent가 첫 결과를 제안하고 대화로 다듬어 Spec 문서 채우기, Spec 확정
- 화면 위 로드맵(1~5단계)과 "지금 할 일" 안내
- 끝난 단계 다시 고치기와 "다시 확인 필요" 처리
- 각 문서 화면 보기와 `.md` 내려받기
- 진행 상황을 이 브라우저에 보존해 새로고침하거나 다시 들어와도 이어서 하기

제외는 [Off-limits](#off-limits)를 봅니다.

## Acceptance criteria

시작과 API 키

- 키 입력란이 비었거나, 넣은 키로 Claude 호출이 실패하면 "키를 확인하지 못했어요" 안내가 뜨고 다음 화면으로 넘어가지 않습니다.
- 유효한 키를 넣고 "시작하기"를 누르면 만들 것 찾기 화면으로 갑니다.
- 키는 이 브라우저에만 보관됩니다. 서비스 서버가 키를 저장하거나 로그에 남기지 않습니다.
- 어느 단계에서든 "API 키 변경"으로 시작 화면에 돌아가 키를 바꿀 수 있고, 진행 상황은 그대로 남습니다.
- 대화 도중 키가 거부되면(만료, 한도 초과 등) 대화 화면에서 원인을 알리고 키를 바꾸러 갈 수 있게 합니다. 이미 쓴 대화와 문서는 사라지지 않습니다.

1단계 만들 것 찾기

- 아이디어를 적고 "이 아이디어로 시작"을 누르면 서비스 방향 단계로 넘어가고, 적은 아이디어가 agent의 첫 질문에 반영됩니다.
- 아이디어 칸이 비었을 때 "이 아이디어로 시작"을 누르면 넘어가지 않고 무엇을 적으면 되는지 알려 줍니다.
- "쓸 수 있는 재료 보기"를 누르면 PRODUCT.md의 재료가 공개 데이터 / AI가 하는 일 / 저장과 로그인 / 알림 네 묶음으로 보입니다.
- 재료를 하나도 고르지 않으면 "고른 재료로 아이디어 받기"를 누를 수 없습니다.
- 재료를 고르고 아이디어를 받으면, 기다리는 동안 로딩 표시가 나오고, 이어서 제목과 한 줄 설명이 있는 아이디어 3개가 나옵니다. "다른 아이디어 보기"로 다시 받을 수 있습니다.
- 아이디어를 하나 골라야 "이 아이디어로 시작"을 누를 수 있고, 누르면 서비스 방향 단계로 넘어갑니다.

2·3단계 대화와 문서

- 대화 화면은 왼쪽(좁은 화면에서는 위)에 agent와의 대화, 오른쪽(좁은 화면에서는 아래)에 그 단계의 문서를 보여 줍니다.
- 메시지를 보내면 agent 응답을 기다리는 동안 로딩 표시가 나오고, 응답이 오면 문서의 해당 항목이 채워지거나 바뀝니다. 새로 바뀐 부분은 잠시 강조됩니다.
- 빈 메시지는 보내지지 않습니다.
- 빠른 답 버튼("잘 모르겠어요, 예시를 보여주세요" 등)을 누르면 그 문장이 메시지로 보내집니다.
- 서비스 방향 문서는 한 줄 정의, 사용자와 상황, 문제와 지금의 대안, 약속하는 변화, 핵심 루프 항목을 가집니다. 아직 정해지지 않은 항목은 "대화로 채워지는 중"으로 보입니다.
- 첫 Spec 문서는 사용자가 얻는 결과, 범위, 확인 방법, 이번엔 하지 않는 것 항목을 가집니다.
- 3단계에 들어가면 agent가 서비스 방향을 바탕으로 첫 결과 하나를 먼저 제안합니다.
- "방향 확정하고 다음으로"를 누르면 2단계가 완료되고 3단계로 갑니다. "Spec 확정하기"를 누르면 3단계가 완료되고, 두 문서를 내려받을 수 있는 완료 화면이 나옵니다.
- 각 문서의 `.md 내려받기`를 누르면 지금 화면에 보이는 문서 내용과 같은 Markdown 파일이 내려받아집니다.
- Claude 호출이 키 문제 외의 이유로 실패하면 대화 안에 실패를 알리고 같은 메시지를 다시 보낼 수 있게 합니다.

로드맵과 다시 고치기

- 1~3단계 화면 위에 1~5단계 로드맵이 보이고, 각 단계는 완료 / 지금 / 아직 / 다시 확인 / 잠김 중 하나로 표시됩니다.
- 4 구현과 5 배포는 잠김으로 보이고 누를 수 없습니다. 무엇인지 궁금한 사용자를 위해 "다음 업데이트에서 열려요"를 알려 줍니다.
- "지금 할 일" 줄은 현재 단계에서 사용자가 해야 할 행동을 한 문장으로 보여 줍니다.
- 완료된 단계를 누르면 그 단계 화면으로 가서 대화를 이어 고칠 수 있습니다.
- 3단계가 완료된 뒤 2단계를 고치면 2단계 화면에 "고치는 중" 안내가 보이고, 서비스 방향 문서가 실제로 바뀌면 3단계는 내용을 유지한 채 로드맵에 "다시 확인"으로 표시됩니다.
- "다시 확인" 상태인 3단계에 들어가면, 무엇이 바뀌었는지와 함께 "바뀐 부분 반영하기" / "그대로 둘게요"가 보입니다. "바뀐 부분 반영하기"를 누르면 agent가 바뀐 방향에 맞춰 Spec을 고치고, 어느 쪽이든 "다시 확인" 표시가 사라집니다.
- 1단계를 다시 고쳐 아이디어가 바뀌면, 이미 진행한 2·3단계도 같은 방식으로 내용을 유지한 채 "다시 확인"으로 표시됩니다.

보존

- 새로고침하거나 브라우저를 닫았다가 다시 열어도 마지막 단계, 대화, 문서, 단계별 상태가 그대로 이어집니다.

화면

- 화면 폭 390px, 768px, 데스크톱에서 모든 화면의 내용과 버튼이 잘리거나 가려지지 않습니다.
- 모든 화면 문구는 한국어입니다.

agent 대화 품질(실행마다 결과가 달라 eval로 증명)

- 평가 사례: 구현 단계에서 이 폴더에 평가 사례 파일을 만듭니다. PRODUCT.md 재료 목록의 조합 10개와, 직접 적은 아이디어 10개(비개발자 말투의 막연한 아이디어 포함)로 이루어진 20개 사례를 쓰고, 프롬프트를 다듬는 데 쓴 사례와 겹치지 않게 둡니다.
- 아이디어 추천: 추천된 아이디어 3개 모두가 고른 재료만으로 설명되는 사례가 재료 사례 10개 중 9개 이상이어야 합니다.
- 한 번에 하나씩 묻기: 2·3단계 agent 응답 중 질문이 최대 하나인 응답이 90% 이상이어야 합니다.
- 첫 Spec 크기: 20개 사례 중 18개 이상에서 첫 Spec이 네 항목을 모두 채우고, 사용자 결과가 하나뿐이며, 그 결과의 범위가 사용자가 한 번에 직접 써 보고 확인할 수 있는 크기여야 합니다. 판정 기준은 평가 사례 파일에 함께 적습니다.

## Constraints and rationale

- agent의 모든 Claude 호출은 사용자가 넣은 키로 합니다. 운영자 키로 대신하지 않습니다. — [llm-usage-billing](../../decisions/llm-usage-billing.md)
- 첫 결과는 핵심 루프의 1~3단계까지입니다. — 한 번에 구현하고 브라우저에서 직접 대화해 보며 확인할 수 있는 크기로 정했습니다. 4·5단계는 코드 실행, GitHub·Vercel 연결, 배포 확인이 함께 얽혀 다음 결과로 다룹니다.
- 앞 단계를 고치면 뒤 단계는 지우지 않고 "다시 확인 필요"로 표시합니다. — 작은 수정에도 앞서 한 작업을 잃지 않게 하고, 바뀐 부분만 다시 다루게 해서 대화를 가볍게 유지합니다.
- 로드맵에는 잠긴 4·5단계까지 다섯 단계를 모두 보여 줍니다. — 처음 해 보는 사용자가 개발 전체 순서를 처음부터 알 수 있게 하려는 PRODUCT.md의 요구입니다.
- 현재 단계와 다음 행동이 항상 보여야 합니다. — PRODUCT.md 경험 원칙.

## Assumptions

다음은 agent가 정한 기본값입니다. 사용자가 언제든 바꿀 수 있습니다.

- 로그인이 없으므로 진행 상황은 이 브라우저에만 저장하고, 한 번에 프로젝트 하나만 다룹니다. 다른 기기나 다른 브라우저로는 이어지지 않습니다.
- API 키는 이 브라우저에만 보관하고, agent에게 요청할 때만 함께 보냅니다.
- 쓸 Claude 모델은 구현할 때 `claude-api` 스킬과 공식 문서로 대화형 작업에 맞는 최신 모델을 고릅니다.
- 아이디어 추천 개수는 3개입니다.
- 다운로드 파일 이름은 `서비스방향.md`, `첫Spec.md`입니다.
- 서비스 이름이 아직 없으므로 화면 위쪽에는 프로젝트 이름(처음엔 "새 프로젝트", 아이디어가 정해지면 그 제목)만 보여 줍니다.

## Off-limits

- 로그인과 계정 — PRODUCT.md의 권한별 관제가 필요해지는 결과에서 다룹니다. 이 결과는 로그인 없이도 핵심 루프 앞부분을 확인할 수 있습니다.
- 4단계 구현과 5단계 배포, GitHub·Vercel 연결 — 다음 결과입니다.
- 관제 화면(일반 사용자, 운영자), 에러 기록과 운영자 알림 — 시스템이 배포된 뒤에 의미가 있어 이후 결과로 미룹니다.
- 구현 단계의 기술 자문(효율·대중성 순 추천) — 4단계에 속합니다.
- 여러 프로젝트 관리, 다른 기기와 동기화 — 로그인이 생기는 결과에서 다룹니다.
- 개발 히스토리와 개발 일지 export — 구현·배포 단계의 기록이 생긴 뒤에 다룹니다.

## Deferred

- 에러 기록과 운영자 알림(PRODUCT.md 성공 신호) — 알림을 받는 방법이 미정입니다. 이 결과에서는 에러를 사용자 화면에만 알립니다(임시 동작). 관제 결과를 shape할 때 다시 엽니다.
- 진행 상황의 서버 보관 — 이 결과에서는 브라우저에만 저장합니다(임시 동작). 로그인이 들어오는 결과를 shape할 때 다시 엽니다.

## Remaining risks

- 사용자 본인 키를 요구하므로, 비개발자가 키를 발급받는 단계에서 이탈할 수 있습니다. "키는 어디서 받나요?" 안내의 질이 시작 경험을 좌우합니다.
- 브라우저에만 저장하므로, 브라우저 데이터를 지우면 진행 상황이 사라집니다. 내려받은 `.md`만 남습니다.
- agent 대화 품질은 모델과 프롬프트에 따라 흔들립니다. 위 eval 목표에 못 미치면 확정 전에 프롬프트를 다듬어야 합니다.

## Setup before implementation

- 구현자가 쓸 테스트용 Claude API 키 — 키 확인, 대화, eval 실행을 실제로 돌려 보기 위해 필요합니다. 완료 조건: 그 키로 앱 밖에서 Claude Messages API를 직접 호출해 정상 응답을 받는 것.

## Post-release check

None.
