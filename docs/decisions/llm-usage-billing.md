# AI 사용료 부담

## Decisions

- 서비스를 쓰는 사람이 운영자 한 명뿐인 동안에는, 서버가 `.env.local`의 `AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_DEPLOYMENT`로 LLM을 호출하고, 시작 화면의 키 입력은 생략합니다(2026-11-19 사용자 결정). 사용료는 그 키의 주인인 사용자 본인이 냅니다.
- 서버에 이 설정이 없으면 브라우저에 입력해 저장한 연결 정보로 호출하는 기존 방식이 보조 경로로 동작합니다.
- 사용자가 둘 이상이 되면 서비스 운영자 키로 다른 사람의 agent 작업을 대신 결제하지 않고, 각자 본인의 API 키를 연결하게 합니다. 이 방향은 그대로입니다.
- 제공자는 당분간 Azure OpenAI입니다(2026-11-19 사용자 결정). 사용자가 가진 키가 Azure OpenAI 키여서 Claude 대신 정했고, 기간이 "우선"이라 임시 성격입니다. 키 외에 엔드포인트와 배포 이름도 사용자가 연결합니다.

## Why

운영자 키를 쓰면 비개발자의 시작 허들은 낮아지지만 사용량이 운영자 비용으로 쌓이고 사용자별 한도를 따로 관리해야 합니다. 사용자 본인 키를 쓰게 해서 운영자 비용 부담을 없애고, 그 대신 키 발급과 연결이라는 시작 허들을 감수합니다. [deployment-ownership](deployment-ownership.md)처럼 사용자가 자기 자원을 직접 소유하고 부담하는 방향과도 맞습니다.

## Reconsider when

- 운영자가 아닌 두 번째 사용자가 생길 때(서버 키 사용을 끝내고 사용자별 키 연결을 되살립니다)
- API 키 연결 단계에서 비개발자 대부분이 이탈한다는 실제 사용 근거가 나올 때
- Claude 키로 돌아가거나, 제공자를 사용자가 고르게 하려 할 때

## Still-rejected alternatives

- Claude 키 유지 — 사용자에게 Claude API 키가 없어 별도 발급이 필요합니다.
- 운영자 키와 사용자별 사용 한도 — 사용량 비용이 운영자에게 쌓입니다. 키 연결 이탈이 확인되면 다시 검토합니다.
