# 배포 소유권

## Decisions

- agent가 사용자를 위해 만든 시스템의 코드 저장소와 배포 대상은 사용자 본인의 계정과 인프라입니다. 서비스 운영자 계정에 사용자 시스템을 모아 배포하지 않습니다.
- 배포 대상은 Vercel로 고정하지 않습니다. 사용자가 Vercel 같은 호스팅 서비스나 자기 조직의 내부 서버 중에서 고릅니다.
- agent의 기술 자문(추천 기술과 우선순위)은 사용자가 고른 배포 대상에 맞춰 달라집니다.
- 사용자가 자기 계정이나 서버를 서비스에 연결하는 과정은 제품 흐름의 일부로 설계합니다.

## Boundaries

- 첫 범위에서 agent가 자동으로 배포하는 대상은 사용자 본인의 Vercel뿐입니다. 내부 서버를 비롯한 다른 배포 대상은 다양성이 커서 이후로 미룹니다. 이 제한은 배포 대상을 고정하는 결정이 아닙니다.
- 이 서비스 자체(가이드 웹앱과 관제 화면)를 운영하는 배포는 이 결정의 대상이 아닙니다.
- 연결 방식(OAuth, 토큰, 접속 정보 등), 연결 시점, 배포 대상별로 agent가 어디까지 자동으로 하는지는 이 결정이 정하지 않습니다.

## Why

사용자가 만든 시스템의 코드와 호스팅을 처음부터 사용자가 소유하게 하려고 선택했습니다. 운영자 계정 한 곳에 배포하면 계정 연결 허들이 없고 관제 데이터도 모으기 쉽지만, 소유권과 비용이 운영자에게 남고 사용자가 나중에 시스템을 옮겨 가야 합니다. 그 대신 비개발자에게도 계정 연결이라는 시작 허들이 생기는 것을 감수합니다.

사용자 조직에 따라 외부 호스팅 대신 내부 서버에 올려야 할 수 있으므로, 배포 대상을 하나로 고정하지 않고 기술 자문이 그 선택을 따르게 합니다.

## Reconsider when

- 계정 연결 단계에서 비개발자 대부분이 이탈한다는 실제 사용 근거가 나올 때

## Still-rejected alternatives

- 서비스 운영자 계정에 모든 사용자 시스템을 배포 — 소유권과 호스팅 비용이 운영자에게 남고 사용자가 시스템을 가져가려면 별도 이전이 필요합니다. 계정 연결 이탈이 확인되면 다시 검토합니다.
- 배포 대상을 Vercel 하나로 고정 — 내부 서버만 쓸 수 있는 조직의 사용자는 배포까지 갈 수 없습니다.
